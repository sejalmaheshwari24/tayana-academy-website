# DNS cutover — tayanaacademy.com

Moving the domain off Lovable to this Vercel deployment. Written against the
site as it stands; the "verify" items are things that are wrong *today* on
purpose and must change when the real domain goes live.

Preview today: `https://tayana-academycd.vercel.app`

## The cutover

- [ ] Add `tayanaacademy.com` and `www.tayanaacademy.com` in Vercel →
      Project → Domains; pick one as primary and redirect the other
- [ ] Update DNS at the registrar to Vercel's records; remove the Lovable records
- [ ] Wait for the certificate to issue before announcing

## Verify on the live domain

The first item is the one that bites silently.

- [ ] **`curl -sI https://tayanaacademy.com/ | grep -i x-robots-tag` returns
      NOTHING.** The preview is de-indexed by a host-conditional header in
      `vercel.json` scoped to `*.vercel.app`. It should stop applying on the
      custom domain automatically — but that has never been tested, because it
      cannot be until the domain resolves. If the header is still present, the
      site will not be indexed at all
- [ ] `curl -sI https://tayana-academycd.vercel.app/` still HAS the header
      (the preview stays de-indexed)
- [ ] All 21 pages return 200 on the real domain
- [ ] Old track slugs still 308 to the new pages (four redirects in `vercel.json`)
- [ ] `assets/` and `assets/logos/` (31 files) load — no 404s
- [ ] `python3 scripts/audit-course-language.py` passes; it also runs as the
      Vercel build command, so a failing audit blocks the deploy
